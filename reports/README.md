# Conformance reports

## Snapshot certification and live freshness

A `current` report certifies the exact immutable subject set observed by that run. It is not an indefinite claim about moving remote branches. Every report includes `freshnessValidity.observedAt`, `validUntil`, `maximumAgeSeconds`, and `expiryFreshness`. Consumers MUST treat a `current` snapshot as `indeterminate` after `validUntil` until a newer exact remote observation is published. The hosted page and CLI apply this same rule.

The 75-minute maximum age is explicit and covers the hourly reconciliation schedule plus bounded delivery jitter. Repository/ref/SHA identity remains in `subjectState`; package-version equality never extends the deadline or suppresses source-revision invalidation. A later successful exact-state run creates a new snapshot. Historical certifications remain immutable evidence of what they proved at their own observation time.

`reports/main/latest.json` is generated by `npm run conformance` as the latest public evidence projection. A production caller must persist or restore its certified copy with `--certified-report`; generated reports are not committed by default.

Historical reports may be published by CI under `reports/history/` or GitHub Pages. They are not committed by default.

The report separates machine-proven failures from warnings and invariants that still need semantic review. The authoritative Provider membership, exact revisions, and exclusions live in `conformance/repositories.yaml`; repository discovery never changes that set. Freshness compares immutable observations made before and after rule execution with a previously certified, clean, current mainline report. Matching stable state is `current`, stable drift is `stale`, and missing, invalid, incomplete, dirty, or execution-mutated state fails closed to `indeterminate`. The default production path reads the prior `reports/main/latest.json` before atomically replacing that projection; `--certified-report` restores a separately persisted baseline. The CI compatibility flag gates on the derived result and cannot turn failed restoration into current evidence. Candidate evidence requires a separate output and cannot replace canonical mainline evidence.
