# Conformance reports

`reports/main/latest.json` is generated by `npm run conformance` as the latest public evidence projection. A production caller must persist or restore its certified copy with `--certified-report`; generated reports are not committed by default.

Historical reports may be published by CI under `reports/history/` or GitHub Pages. They are not committed by default.

The report separates machine-proven failures from warnings and invariants that still need semantic review. The authoritative repository/ref catalogue, repository classifications, complete Provider membership, exact Provider revisions, exclusions, product publications, and supported channel live in `conformance/repositories.yaml`; repository discovery never changes those claims. Each report resolves the configured source ref to the observed checkout SHA. Freshness compares immutable observations made before and after rule execution with a previously certified, clean, current mainline report. Matching stable state is `current`, stable drift is `stale`, and missing, invalid, incomplete, dirty, or execution-mutated state fails closed to `indeterminate`. The default production path reads the prior `reports/main/latest.json` before atomically replacing that projection; `--certified-report` restores a separately persisted baseline. The CI compatibility flag gates on the derived result and cannot turn failed restoration into current evidence. Candidate evidence requires a separate output and cannot replace canonical mainline evidence.
